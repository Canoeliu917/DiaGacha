# 版本记录与后续维护

[查看全部版本](../CHANGELOG.md) · [打开当前游戏](https://canoeliu917.github.io/DiaGacha/)

每个工作版本保留一份 `CHANGELOG-v版本号.md`。后续游戏更新时，与源码一同补齐以下记录；仅整理文档时不虚增游戏版本号。

1. 写明这次解决的问题、实际改动，以及用户能看到的变化。
2. 记录卡池、数值、来源、图像或交互的变动范围。没有修改的内容不算本版新增成果。
3. 记录实际执行的检查、结果及未验证事项，区分自动测试、浏览器视口和实体手机；文献阅读与代码测试分开记录。
4. 提交游戏后，加入固定提交链接与源码快照；同步更新根目录 `CHANGELOG.md`、`README.md` 的最新版导航。默认首页与发布分支的导航保持一致。
5. 发布后确认构建完成、公共入口可访问且内容对应当前版本，再补记发布结果。已完成代码提交不等于已经上线。

旧日志不因后续改动而覆盖。若旧版有错误，新增勘误或在后续版本指出，不把后续结果写成旧版已经完成。提交日期与部署时间分别记录；没有证据时不补造历史通过数量、精确部署时间或版本标签。

## 记录模板

```markdown
# v版本号 · 本次主题

提交日期：YYYY-MM-DD（UTC+8）。
固定提交：[提交号](完整提交链接) · [源码快照](完整快照链接)

## 改动

- 具体问题与修改后的行为。

## 验证与边界

- 实际执行的检查与结果。
- 尚未完成或不在本次范围内的核查。

## 发布

- 已确认的部署与内容核对结果，或尚未发布的状态。

[返回版本总目](../CHANGELOG.md)
```

在线游戏网址始终显示最近发布的游戏。`?v=数字` 是缓存标识，不是历史版本切换器；需要回看旧版时使用对应提交的源码快照。
